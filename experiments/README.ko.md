# AutoHarness 실험 버전 관리

프롬프트·하네스·설정·평가 코드와 작은 결과 요약은 이 저장소에서 관리합니다. 모델 가중치, 대용량 데이터/원시 결과, 비밀은 외부 저장소에 두고 SHA256과 안정적인 참조만 기록합니다. 이 문서는 관리 기반이며 새로운 실행 결과가 아닙니다.

## 확인한 작업 공간

2026-10-04 기준 origin은 https://github.com/LeeDongHyun00/AutoHarness.git 입니다. 관리 기반 준비 당시 로컬 브랜치 work는 첫 커밋이 없었고 기존 파일/변경도 없었습니다. 읽기 전용 `git ls-remote origin`은 성공했지만 ref를 반환하지 않았습니다. 이 결과를 다른 스레드에 보존된 미커밋 구현이 없다는 뜻으로 해석하지 않습니다. 해당 구현은 이 작업에 가져오거나 덮어쓰지 않았습니다. 추후 원격 ref나 구현이 확인되면 기존 구조를 우선 재사용합니다.

## 최소 폴더 규약

- `experiments/run-manifest.template.json`: 새 실행의 기록 템플릿.
- `experiments/run-manifest.schema.json`: 템플릿과 실행 manifest의 구조 검증용 JSON Schema.
- `experiments/runs/<run-id>/manifest.json`: 작은 실행 메타데이터. 이번에는 실행 폴더를 만들지 않습니다.
- `experiments/runs/<run-id>/summary.md`: 원문 응답을 포함하지 않은 결과 요약·제한·분모.
- `experiments/local/`: 임시 상태용 ignored 경로. 영구 보관이나 접근 격리 수단이 아닙니다.

프롬프트·하네스·설정·평가 구현은 나중에 확인되는 기존 프로젝트 경로를 그대로 쓰고 manifest에서 경로+해시로 참조합니다. 이 작업에서는 중복 구현 폴더, 기존 평가 패키지 사본, 데이터 사본을 만들지 않았습니다. 모델·원시 결과는 외부에서 유지하고, 체크포인트는 세션 종료 전에 승인된 영구 저장소에 보존합니다.

## 실행 고정과 provenance

1. 실행 전에 코드 commit, branch, dirty 여부, 모델 revision/파일 SHA256, 입력 데이터 SHA256, 프롬프트/하네스/설정/평가 코드 해시를 기록합니다. 작은 샘플이라도 동일한 run-id를 다른 설정에 재사용하지 않습니다.
2. 커밋이 없으면 commit=null, head_state=unborn으로 명시합니다. dirty=true 실행은 commit만으로 재현할 수 없습니다. 관련 untracked 파일까지 포함한 검토된 소스 스냅샷의 외부 참조/해시가 필요하며 비밀·정답을 함께 보관하지 않습니다. git diff만으로 untracked 파일을 복원할 수 없습니다.
3. runtime에는 플랫폼, OS/Python, GPU 수·종류·메모리, 드라이버/CUDA, 엔진 commit/버전/바이너리 SHA256, 빌드 옵션을 기록합니다. 서로 다른 GPU 실행은 환경 차이를 표시합니다.
4. seed, temperature, context/output token 상한, thinking/reasoning budget 등 생성 설정을 고정합니다. tokenizer/template 사전검증 상태도 기록합니다.
5. planned/completed/failed/ambiguous 요청 수, 입력/출력 토큰, 벽시계 시간과 지표별 numerator/denominator를 저장합니다. 합계에 미실행·결측치를 0으로 채우지 않습니다. 요청별 원문/시간/토큰은 외부 JSON으로 보관하고 manifest에는 그 참조와 해시를 둡니다.
6. 중단된 요청은 완료 여부가 불명확하므로 자동 재시도하지 않습니다. 재시도는 별도 attempt ID와 예산을 기록합니다. 설정이나 판정 기준을 바꾸면 새 실행/분석 버전을 만듭니다.

상태가 planned인 템플릿은 null 필드를 허용합니다. 이 schema 검증은 실행 허가가 아닙니다. 실제 실행 전에는 null provenance를 채우고, 완료 보고에는 관측값과 미확인 값을 구분해야 합니다. 해시는 무결성 확인이며 기밀성·권한을 제공하지 않습니다.

## 숨겨진 정답과 모델 접근 경계

**private-eval 폴더, 별도 브랜치, .gitignore만으로 정답/테스트가 격리되었다고 주장하지 않습니다.** 모델이 저장소·Git 히스토리·파일 탐색에 접근한다면 같은 저장소의 정답을 읽을 수 있습니다. 숨겨진 정답/테스트는 별도 권한을 가진 비공개 저장소 또는 평가자 전용 저장소에 보관하고 생성 런타임에 마운트하지 않습니다. 원시 결과에도 입력·개인정보·정답이 포함될 수 있으므로 접근을 제한합니다.

모델에게 노출해도 되는 평가 로직은 Git에 둘 수 있지만, 숨겨진 테스트를 내장한 평가 코드는 위 접근 경계 밖에 둡니다. 외부 참조에는 만료되는 서명 URL, 토큰, Authorization 헤더, 전체 환경변수를 넣지 않습니다. 내부 평가 자산의 이름/해시 공개도 소유자가 검토하며 민감하면 공개 manifest에는 null을 두고 권한이 있는 내부 manifest에만 기록합니다.

ignore는 실수 방지 장치일 뿐입니다. 이미 tracked인 파일에는 소급되지 않으며 `git add -f`로 우회할 수 있습니다. commit 전 staged diff와 파일 목록을 확인하고 노트북 output을 제거합니다. 비밀이 들어갔다면 단순 삭제 커밋으로 해결됐다고 간주하지 않습니다.

## 지표의 분모와 사후 진단

원본 형식, 의미, 코드 기능, 하네스 구조, 하네스 실제 유용성을 별도로 보고합니다. 형식 실패 뒤 의미가 미채점이면 null이지 성공이 아닙니다. AST 계약 위반과 검증기 한계를 분리하고, 판정 가능한 건만의 평균에는 그 분모와 전체 커버리지를 함께 표시합니다.

부모가 전달한 최신 216회 실행 요약(이 checkout에서 원시 결과를 가져오거나 재검증하지 않음):

| 분석 | 분자/분모 | 해석 |
|---|---:|---|
| 원문 JSON strict 통과 | 0/216 | 보고에 따르면 모두 코드 펜스 포함 |
| 바깥 fence만 제거한 의미 진단 | 128/162 | **사후 진단**, 의미 채점 대상 요청 162개 기준 |
| 바깥 fence만 제거한 코드 all-tests | 11/18 | **사후 진단**, 코드 요청 18개 기준 |

fence 제거 결과를 원문 계약 준수 성능으로 바꾸어 보고하지 않습니다. 162와 18은 서로 다른 지표의 대상 집합이며 더해서 전체 성공률을 만들지 않습니다. 이번 숫자는 제공된 요약만 옮겼으므로 원시 artifact 해시/실행 식별을 확인하기 전 verified 결과 manifest로 등록하지 않습니다. 216개는 24계열의 조건/표현 반복이며 독립 표본 216개가 아닙니다. 하네스 계획 생성과 제한 AST 기능 검증을 실제 저장소의 downstream 효과 검증으로 과장하지 않습니다.

## 후속 구현 통합 전 결정

- 다른 스레드의 실제 구현을 어느 commit/branch에서 통합할지, 원격 기본 브랜치와 작업 브랜치를 어떻게 정할지.
- 저장소 공개 범위와 모델에게 허용할 경로/도구, 별도 평가자 저장소의 실제 접근 권한.
- 모델/결과 외부 저장소, 보존 기간, 안정적 artifact ID 규약.
- dirty 실행을 허용할 조건과 스냅샷 보관 방식, 결과 게시 전 검토자.
- 이 관리 기반 네 파일의 첫 commit/push는 사용자 승인에 따라 main으로 진행합니다. 실제 구현 통합과 후속 PR은 별도 범위입니다.
